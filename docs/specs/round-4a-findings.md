## 3. 戦略別考察

### donchian（-0.176 BTC / +0.063 ETH）
- BTC: R3 で稼いでいたショート（逆ブレイクアウト）がフィルタで消えた結果、Sharpe 低下。BTC の長期上昇トレンド下でもショート抜けは短期的に機能していた
- ETH: 僅かに改善したが誤差範囲

### ma-crossover（-0.023 / -0.180）
- 元々「移動平均クロス = トレンド追従」なのでシグナルは既にトレンド順方向に偏っている。フィルタは**ほぼ二重適用で無効**
- ETH の悪化は、fresh cross のタイミングで SMA50 が未更新だった（cross 発生時の close は SMA50 より下だが本当の下落は先）ケースで排除されたもの

### rsi-reversion（+0.060 BTC / **-0.805** ETH）← 最大の悪化
- RSI reversion の本質は「トレンドに逆らう」。TF は「トレンド順方向のみ」→ **戦略哲学に直接矛盾する**
- ETH のみで大幅悪化した理由: Round 3 の ETH での rsi-reversion は「トレンド転換初期の反転」を捉えて 0.667 の Sharpe を出していた。TF で「SMA50 上での long のみ」に限定すると、それらの反転は SMA50 下で発生するため全除外され、残るのは「順トレンド中の一時的調整ロング」だけ → 勝率低下
- BTC ではもともと負の Sharpe（-0.164）で悪化余地少なく、-0.104 と微増

### nr7-breakout（-0.135 / -0.023）
- NR7 は「ボラ圧縮 → 方向無関係な拡張」。TF を掛けると半分の方向が無効化される
- BTC でわずかに悪化、ETH でほぼ変化なし

---

## 4. 教訓

1. **「トレンドフィルタ」は万能薬ではない**: モメンタム系戦略には二重適用で効果薄、逆張り系戦略には戦略哲学を殺す
2. **過学習は relocated されただけ**: IS→OOS drop は相変わらず 40-118%。単にフィルタで取引数を減らしても、残った取引の IS 最適化 vs OOS 実績の乖離は同じ
3. **Max DD は改善、Sharpe は不変**: リスクは下がるが同時にリターンも下がる → 「リスク調整後パフォーマンス」は不変。フィルタは**リスク管理ツール**としては意味があるが、**エッジ生成ツール**ではない
4. **Beats BH は donchian/ETH でかろうじて成立**: でも 0.808 < 1.0 の主KPI未達で救済と呼べない

## 5. Round 4b への含意

**「単純な技術指標ベース戦略 + フィルタ」では crypto の OOS 問題を解決できない**ことが確定。本番の研究を続けるなら、**戦略のデータソースまたは数学的構造を根本から変える**必要がある。

優先順位（設計 §8 からの再検討）:

### 推奨: C（ペアトレード BTC-ETH）

**理由:**
- データ追加不要（既存 yfinance で BTC/ETH が揃っている）
- 構造が根本的に違う: spread の mean-reversion は **個別銘柄のトレンドフォローとは別エッジ**
- 実装コスト中（新しい engine が必要だが既存 framework と分離可能）
- 理論的裏付けあり: BTC-ETH は高相関でペアになりやすい（過去研究多数）

### 次点: A（オンチェーン指標）

**理由:**
- 教師なし特徴量の追加は長期レジーム判定に強い（MVRV、NUPL など）
- ただし **データソース確保が課題**: Glassnode 有料、CoinMetrics / Santiment 一部無料、自前ノード不要
- 実装より **データ取得 pipeline 整備**に時間がかかる

### 保留: D（マーケット・マイクロストラクチャ）

- 最もエッジ期待値高いが、**日足 yfinance では不可**。取引所 API 連携＋高頻度データが必要
- Round 5 以降の課題

### 棄却: E（ML）
- 特徴量エンジニアリングに戻ってもまた過学習問題にぶつかる
- まず「異なる戦略クラス」を試してから
